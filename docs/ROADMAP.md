# Lite-PngInfo 版本迭代方案

更新：2026-11-09。已发布基线 v1（`ab6d87c`）；用户授权后的 v2 已在本地实现，尚未提交或发布；v3/v4 为后续计划。本方案整合原始草案、样图、逆向报告及讨论，用户最新确认的取舍优先。

## 已确认的产品取舍

| 项目 | 本轮确认 |
|---|---|
| 四类名称 | NAI、ComfyUI、A1111、Forge |
| NAI | 用户通过 NAI API 生成，按 NAI 元信息处理；不再称为 ComfyUI-NAI，不提供 workflow 功能入口 |
| ComfyUI | 分类模式只展示容易提取且能可靠归属当前图片的信息；其余内容留在 JSON；不提供复杂分支查看器 |
| JSON | 同时提供格式化浏览和复制原文 |
| v4 查询 | 明确区分未找到、缺少哈希、网络失败，并提供有意义的重试操作 |
| 无元信息图片 | 作为正常输入设计空状态，避免空白界面、报错与上张图片的数据残留 |
| 轻量与质量 | 不做过度防御性编程；以功能正确、数据完整和关键流程无回归为前提，减少重复与不必要抽象 |

下面各版的交互细节、内部数据结构和验收方法为开发方案；缩略图、分页等额外优化另列为建议，不自动扩入必做范围。

## 产品方向

保持“拖入图片 → 看懂生成信息 → 本地收藏 → 找回模型”的主线，沿用 Python、Pillow、SQLite 与原生 HTML/JS/CSS。分类视图突出可靠和简洁，任意字段和未知数据仍可完整查看。按 v2 → v3 → v4 分版实施，每版独立验收。

逆向网站值得参考的是任意字段 JSON 浏览和原文保留。它没有提供通用 ComfyUI 语义解析，PNG 压缩文本等路径还有遗漏；本项目应保留 Pillow 读取基础，自行完成适配。

### 轻量实现原则

- 优先简单函数、明确的数据结构与现有依赖。数据分层用于明确原文、解码和分类的职责，不要求建立类层次、插件系统、任务框架或通用恢复机制。
- 在真实边界一次处理必要错误：PNG 有效性与大小、缺失/无效元信息、数据库读写失败、外部查询失败。进入内部后使用约定的数据形状，避免每层重复类型判断、默认值和兜底分支。
- 无元信息是正常业务状态，不靠捕获所有异常伪装成功。未知字段保留原文；程序错误应能被发现和修复，不用宽泛异常处理吞掉。
- 请求去重、旧响应失效、事务等直接解决当前交互和数据问题的措施保留；不增加多层自动重试和猜测性修复。
- 先正确实现本版范围，再消除可确认的重复；只有出现实际需求或测量证据时才引入更多缓存、分页和基础设施。正确性与已有行为优先于行数，验证覆盖真实用户流程和必要边界，不追求组合穷举。

## v2：多来源解析与统一信息面板

状态：本地已实现。实现采用 `metadata.py` 中的简单函数；条目保存原文与后端格式化字符串，不将大整数 JSON 交由浏览器重新解码。ComfyUI 首批支持唯一 SaveImage/SaveImageSimple → VAEDecode → KSampler → 直接 CLIPTextEncode 的提示词；不推测未知图片级文本字段的绑定语义。历史收藏列表暂标“待更新分类”，打开时从原图重解析并写回；首次写回前备份整个 SQLite。

目标：以 NAI、ComfyUI、A1111、Forge 四类组织生成信息，均可切换 JSON；收藏同步来源类别。NAI、A1111、Forge 提取元信息中实际存在的生成参数；ComfyUI 按本轮确认采用精简分类。

### 建议的交互与命名

默认自动识别来源，用户无需先猜格式。各来源复用分类展示组件，根据可用数据显示相应区域；不生成大量全是占位符的参数卡片。无可靠证据时标记“来源未识别”，无生成信息时显示“无生成元信息”，不强行归入四类。

第一类固定命名为 **NAI**。用户已说明样图通过 NAI API 生成，实际保存 NAI 元信息；按 Comment、Description、Software/Source 等信息处理，不需要为调用 API 的宿主工具额外建立类别。

A1111 与 Forge 共用 parameters parser。Forge 本图的版本串以 `f2...` 开头且不含 forge，可作为线索，但证据不足时仍显示 A1111-compatible，不阻塞参数抽取。四类是常见入口，不应成为读取其他 PNG 的限制。

### 数据分层建议

```text
PNG 容器 → entries 原始文本 → decoded 逐字段解码 → 来源证据 → 适配器 → 分类结果
                              ↘ 任意字段浏览与复制原文
```

- `entries[]` 保留顺序、重复 key、文本值、索引；Pillow 字典不能恢复重复条目，为实现保真目标需增加最小范围的文本块读取，覆盖 tEXt/zTXt/iTXt 与 IDAT 后文本。图片解码继续使用 Pillow；不另造通用 PNG 解码器或元数据框架。
- 非文本附属信息单独放 `image_info`，原图字节是最终保真来源；解码文本不是 PNG 文件的逐字节副本。
- 对任意字段做一次 JSON 解码，保留原文、解析结果与必要状态；这些值可附在同一条目上，避免维护多份平行数据。多层字符串解包只在实际样本需要时支持，不预建递归解码框架。
- `source` 保存家族、生成器与识别证据；分类结果按可用数据组织；`models[]`、`loras[]` 仅用于相应来源中可确认的模型数据；`diagnostics[]` 记录无法解释的信息。不为 ComfyUI 建立复杂生成分支模型。
- `schema_version`、`parser_version` 在 v2 就引入，为收藏重解析和 v4 查询缓存预留基础。
- Seed 分类字段用十进制字符串；完整 JSON 的展示/复制也需保持大整数精度，不能仅修复分类字段后继续对原始 JSON 用 `JSON.parse`/`JSON.stringify` 造成舍入。

UI 顶层提供“分类 / JSON”两种模式。JSON 模式按字段格式化浏览有效 JSON，普通文本原样展示；每个字段提供“复制原文”，复制保存的文本值，不通过前端重新序列化。若提供复制全部字段，明确标为“导出原始字段集合”，使用有序条目数组保留重复键，不宣称 PNG 存在一份统一的原始 JSON。无效 JSON 回退原文并提示，不能令整张图读取失败。

### 各适配器重点

| 家族 | 提取策略 | 需要避免的误读 |
|---|---|---|
| NAI | Comment 与 Description、Software/Source 联合识别；顶层正负、基础参数和 v4 角色结构 | 角色文本扁平拼接；把 Source 中的模型名称丢掉；将签名哈希当作模型 SHA-256 |
| A1111 / Forge | 定位生成设置区域，再按引号/括号深度切分键值；抽模型、LoRA 标签与 Lora hashes，同时保留其他设置和原文 | 按任意逗号拆分；把 `Style: vivid, colorful` 正文当参数；把短 hash 当完整 SHA-256 |
| ComfyUI | 图片基本信息；仅展示可确认的图片级提示词，或简单唯一连接中的正负提示词 | 扫描整图汇总 prompt；选最后一个 sampler；将未启用节点当作本图参数 |

NAI 展示元信息中实际存在的正负提示词、步数、seed、CFG/scale、采样器、模型名称等；有 v4 角色结构时分角色展示。没有模型 hash 或 LoRA 数据时不虚构对应信息。A1111/Forge 展示正负提示词、基础参数、checkpoint 名称/hash，以及实际记录的 LoRA、权重与 hash；未记录不等于未使用。

### ComfyUI 精简分类规则

- 始终展示图片自身的文件名、尺寸、格式、大小等基本信息，并标明 ComfyUI 来源。
- 首批生成信息仅考虑正负提示词。工作流中的 text 不天然与本图绑定，不能只因为字段名叫 prompt、存在一个 CLIPTextEncode 或多个节点内容相同就确认归属。
- 优先使用语义明确、与本次保存图片绑定的独立生成文本字段。仅有运行图时，最多支持静态关系明确的简单路径，例如唯一保存输出，经直接解码连接到唯一采样器，其正负输入直接连到可读取文本的已知编码节点。
- 多输出、多采样、未知中间节点、动态选择、禁用/旁支关系不明确，或需要复杂拼接与链路推断时，不展示推测的正负提示词；给出“无法可靠提取本图提示词，请查看 JSON 或导入 ComfyUI”。正负两侧独立判断，能可靠确定的一侧仍可显示。
- 只有 workflow、缺少可读 prompt 运行图时，保留 JSON 与导入提示，不从编辑器画布猜测执行结果。即使符合简单路径，若有冲突证据也必须回退。
- 不在分类模式展示 ComfyUI 的 seed、CFG、步数、采样器、checkpoint、LoRA 或节点清单；不提供分支切换、全图模型汇总、工作流可视化。原始数据在 JSON 中保留。

分类模式统一备注：**“完整工作流请选择 JSON 模式，或将图片直接拖入 ComfyUI。”** 若文件未包含 workflow，可补充“本图未记录 workflow 字段”，不承诺一定能恢复完整工作流。NAI 页面不显示此备注。

当前复杂 ComfyUI 样图作为“保守回退”验收样例：允许不提取提示词，但必须能浏览原始字段、给出说明且不误报参数。另用合成简单图验证容易提取的正负提示词。

### 空状态与异常状态

“未选择文件”“有效图片无生成元信息”“有数据但无法分类”“文件损坏”应分别呈现。

| 输入/状态 | 分类模式 | JSON 模式与操作 |
|---|---|---|
| 未读取图片 | 上传引导；不显示结果空壳 | 无结果可复制，收藏按钮不可用 |
| 有效 PNG，无文本元信息 | 正常预览与基本信息；提示“未发现生成元信息” | 提示“无可展示的文本元信息”；可用的图片附属信息单独展示 |
| 仅 dpi、ICC、色彩信息等 | 提示“未发现生成元信息”，保留基本信息 | 以实际类型展示或编码附属数据，不误当提示词 |
| 有未知文本或无法识别的 JSON | 提示“存在元信息，暂无法分类” | 展示全部实际字段，允许复制原文 |
| 已识别来源，但部分/全部生成字段为空 | 保留来源，说明缺失；仅展示可用项 | 原始字段仍可用，不伪造参数 |
| 只有 ComfyUI workflow | 保留来源与工作流备注；提示未能提取提示词 | 可浏览并复制 workflow |
| 空字符串或空 JSON 对象/数组 | 不渲染为伪造生成参数 | 保留实际存在的字段与原文；空字符串也能准确复制 |
| 单字段 JSON 损坏 | 其他字段正常显示；必要时提示部分解析失败 | 损坏字段回退文本，不导致页面异常 |
| 文件不是有效 PNG、损坏或超限 | 明确读取失败；可重新选择文件 | 不创建成功结果，不允许收藏失败输入 |

有效的无元信息图片仍允许收藏原图，记录空提示词与“无生成元信息”状态；以后打开收藏也显示相同空状态。复制原文在没有文本条目时不可用；复制基本信息应另命名。

每次开始读取新图片时立即失效旧结果和收藏按钮，读取成功后统一替换预览、分类、JSON、来源及未来 v4 的模型查询状态。新图无元信息不能继续显示旧提示词；读取失败不能让旧参数与新文件混在一起。重置、快速换图与并发请求通过任务标识避免旧响应回写。分类界面不得因缺失值而显示 `undefined`、`null`、`NaN` 或整片空白卡片；JSON 原文中实际存在的 `null` 则正常保留。

### 推荐实施切片与验收

| 顺序 | 切片 | 验收重点 |
|---|---|---|
| 1 | 三层数据、任意字段 JSON、版本字段 | 四图原文可用，未知 key、重复 key、无效 JSON、压缩/后置文本、大整数不丢失 |
| 2 | NAI、A1111 / Forge 适配 | 正负与实际记录的参数、模型/LoRA 可抽取；NAI 无 workflow 入口；复杂文本有回归 |
| 3 | ComfyUI 精简适配 | 简单且可确认的正负提示词可读；复杂样图安全回退；分类不展示模型、LoRA 和采样参数 |
| 4 | 分类 UI、空状态、来源标识与收藏兼容 | 无元信息正常预览/收藏；未知与损坏可区分；历史收藏可用；换图不残留旧内容 |

这四步作为 v2 内部验收切片。历史收藏按需用已保存原图重新解析，成功后事务写回，失败保留旧结果；原图、id、创建时间与去重关系维持一致。列表刷新避免每次全量重解析。

## v3：独立收藏大图查看器

用户草案：收藏卡片右上角放大镜，打开大图和侧边分类信息，支持 JSON；查看收藏不覆盖刚读取的内容。

采用覆盖主页面的独立查看器：左侧大图，右侧分类/JSON；内容遵守 v2 各来源的展示规则，ComfyUI 不因进入收藏而额外展示模型、LoRA 和采样参数。窄屏改为上下排列。复用 v2 渲染组件，独立保存收藏 id、请求序号、模式和滚动状态。

参考图借鉴大图比例和信息区分组。NAI 的角色正负卡片属于本项目已有数据语义，适合保留；画师词典、tag 翻译不在当前草案目标内。

首批包括放大镜入口、关闭按钮、Esc 关闭、焦点返回、独立复制和长提示词展开。连续切换和关闭时旧请求不得覆盖新图；关闭后当前读取的文件、预览、解析结果与可收藏状态均应保持。无元信息收藏仍正常显示大图、基本信息与空状态；记录被删除或读取失败时提供说明，仍可关闭。键盘上一张/下一张、缩放和拖拽作为后续增强建议。

验收重点：打开/关闭收藏不覆盖当前读取结果；分类/JSON 与复制准确；无元信息和记录失效不出现空白死界面；连续操作无串图。收藏列表当前读取全部原图并用原图作缩略图，分页/独立缩略图是性能优化建议，测量实际规模后另行确定。

## v4：模型与 LoRA 查询

用户草案：每项可查询 Civitai，成功后点击跳转，失败可重试，支持一键查询全部。

官方公共 REST 文档列出 `GET /api/v1/model-versions/by-hash/:hash`；模型版本信息包含 `id`、`modelId` 与文件哈希，如 AutoV1、AutoV2、SHA256 等。此信息确认了按哈希查版本的路线，**不代表所有截断长度、算法或权限场景都已验证**。接口的最新认证、限流、错误语义与跳转链接在实施时核对并集成验证；本轮未发送样图中的模型 hash 查询。

样图的 A1111/Forge 有短模型/LoRA hash，ComfyUI 图只有文件名、inputs 未见 hash。建议每项记录 hash 原值、可知的算法与证据。图片 SHA-256 仅作收藏身份，不能拿来查模型。

| 内部状态 | 建议界面 | 操作 |
|---|---|---|
| idle / querying | 查询 / 查询中 | 启动请求，查询中防重复 |
| matched | 查询成功 | 打开匹配的模型版本 |
| not_found | 未找到 | 点击重试 |
| missing_hash | 缺少哈希 | 解释无法按哈希查询；如后续支持，可补充哈希 |
| network_error | 网络失败（超时、连接中断等） | 网络恢复后点击重试 |
| service_error / rate_limited | 服务暂不可用 / 请求过于频繁 | 允许后重试，遵守服务返回的等待时间 |

“未找到”必须来自服务明确返回的无匹配结果，不能把网络失败当成未找到。“缺少哈希”不是点击重试可以解决的问题，说明原因并停止无效请求，不显示空转的重试按钮。名称搜索、手动关联和本地模型目录索引不列入本版必做范围。

查询入口跟随分类中的实际模型/LoRA 项，主要覆盖 A1111、Forge 和其他明确有模型身份的数据；ComfyUI 精简分类不为查询额外扫描整个工作流。没有模型项的 NAI、ComfyUI 或普通 PNG 不显示空查询区；有模型名称但没 hash 的条目显示“缺少哈希”。

由本地服务代理查询，只有用户触发时外联；只发送必要 hash。批量查询跳过缺少哈希的条目、按 hash 去重、限制并发并显示进度，结束后汇总成功/未找到/缺少哈希/失败数量；全部缺少哈希时直接说明，无需请求。成功缓存可复用到多张收藏，未找到和网络失败采用不同缓存策略；用户主动重试未找到时可重新查询。存储 modelId、versionId、匹配 hash、时间和来源，不因同名文件复用关联。切换图片后旧查询结果不能写入新图。

验收覆盖匹配成功并跳转对应版本、未找到重试、无 hash 不发请求、超时/断网、限流、重复 hash、部分成功、全部缺失和换图后的旧响应。API 测试优先使用受控响应；实施时另做独立真实接口验证。

## 共通验证与交付

- 解析与 HTTP 回归使用合成 PNG、临时数据库和临时端口；真实四图只在本地验证，公开测试不保存私人提示词。
- v2 必测“有完整元信息 → 无元信息 → 未知元信息 → 损坏文件 → 重新读取正常文件 → 重置”全过程，确保预览、收藏按钮、分类与 JSON 一致；v4 加入查询状态联动验证。
- 增加字段缺失/null/空对象/类型异常、超安全整数 seed、重复文本字段、无效 JSON、压缩文本与后置文本用例。
- 浏览器验证覆盖四类、空状态、模式切换、复制、收藏、重置和快速换图；v3 再覆盖独立查看器，v4 再覆盖查询状态。
- 每版完成时更新 README 与 CHANGELOG，明确已实现能力；保留 Linux 与原生 Windows 运行兼容。提交、push 和发布按用户明确指令执行。
- 精简时确认删除的是重复实现或无消费者的数据；涉及现有接口/历史收藏时先核对兼容性。关键流程回归通过后再交付，不用未经验证的压缩写法换取更少代码。

## v1 轻量性评估

方案评估时核对的代码与已发布 v1 一致。v1 核心源码为 `app.py` 435 行、`static/app.js` 216 行、HTML 69 行、CSS 75 行，合计 795 行、34146 字节（约 33.3 KiB，不含图片、数据库、Python/Pillow 运行时）。运行依赖仅 Pillow，无前端框架或构建工具，整体已经轻量，没有为了精简而重写的必要。

可在对应模块迭代时顺手整理的局部重复：

| 位置 | 观察 | 处理建议 |
|---|---|---|
| 元信息响应 | `raw` 与 `png_text` 输出同一份对象，JSON 序列化后内容重复 | v2 新结构统一来源；读取旧收藏时兼容旧字段，避免永久发送两个副本 |
| 提示词提取 | normalize 先解码 Comment，正负提取又分别尝试解码剩余字符串；无效文本被重复解析，也附带支持了一层 JSON 字符串包装 | v2 集中处理解码；普通字段只解析一次，确有包装样本时明确支持，避免正负各做一遍 |
| 数据库初始化 | `init_db()` 仅调用 `ensure_database()` | 下次修改数据库代码时可合并；节约很小，不单独安排重构 |
| 收藏数据传输 | 列表为摘要读取整张原图；inspect 返回的图片 hash 当前 UI 未使用，收藏时再次计算 | 列表按需取列；是否复用 hash 按数据流决定，不为省一次计算引入多层缓存 |

文件有效性/大小检查、页面文本转义、静态资源路径范围检查、数据库事务和必要锁有具体作用，应保留。数据库目录恢复已有回归覆盖；若调整初始化流程，保留已验证的行为，不能只因其具有恢复性质就删除。

用户的 v1 使用反馈正常，初始化时现有 3 项回归通过；此后 v2 已按授权开发，并在对应模块中整理上述重复实现。运行依赖仍仅 Pillow。每版使用必要回归验证，避免为省行数破坏行为。
